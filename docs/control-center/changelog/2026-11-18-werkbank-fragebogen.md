## 2026-11-18 · Fragebogen: Fragen von Claude zu Werkbank-Aufgaben

- **Geaendert:** Kommt ein Claude-Lauf bei einer Werkbank-Aufgabe nicht weiter, legt er mit `npm run -s werkbank:frage -- neu --datei <json>` eine Frage an (privat: `$TP_PRIVAT_DIR/werkbank-fragen.json`). „Entscheidungen“ zeigt oben „Fragen von Claude (n)“: je Frage Aufgabe, Frage, Optionen (Empfehlung zuerst, markiert und vorgewählt), optional Ergänzung, ein Knopf „Antwort senden“; darunter „Beantwortet – Claude macht beim nächsten Lauf weiter“. Die Zahl zählt im Menüzähler („Weitere Bereiche“/„Mehr“) mit und steht auf Heute als eine Zeile, wenn > 0. Der nächste Lauf holt Antworten mit `beantwortet` ab und meldet `uebernommen <id>`. API: `GET /api/werkbank/fragen`, `POST /api/werkbank/antworten` (Rolle „lesen“: 403 für beides).
- **Getestet:** `operations/tests/werkbank-fragen.test.mjs` (Befehl, Prüfungen, Lesefehler-Regel), `docs/ai-dashboard/tests/werkbank-fragen-api.test.mjs` (Rollen, Name aus der Sitzung, keine zweite Antwort), `werkbank-fragen-ansicht.test.mjs`; `npm run -s pruefen` grün; `dashboard:pruefen` heute/freigaben bei 1440–360 px nur OK, 0 px Überlauf. Klickstrecke gegen die Kopie: 2 Fragen → Option per Pfeiltaste geändert, Ergänzung getippt, gesendet → „Fragen von Claude (1)“, Datei mit Antwort und Name aus der Sitzung, Menüzähler 1, keine JS-Fehler.
- **Risiken/Annahmen:** Zwei Schreiber (Claude-Lauf und Server) auf einer Datei; beide lesen unmittelbar vor dem Schreiben neu und schreiben atomar, ein Zusammenstoß in derselben Millisekunde wäre verloren (keine Sperrdatei). „Entscheidungen“ hat seit #2143 keinen eigenen Menüpunkt; die Zahl hängt deshalb an „Weitere Bereiche“, der Weg führt über die Zeile auf Heute.
- **Naechste Stufe:** Den geplanten Lauf `werkbank-claude-auftraege` auf `werkbank:frage` umstellen (Hauptsitzung).
